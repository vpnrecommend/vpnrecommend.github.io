第一章 碰撞系统的三维架构

1.1 物理层面的实体交互

当刻晴的星斗归位撞击丘丘人盾牌时迸发的金属火花，或是诺艾尔挥舞巨剑将敌人砸向岩壁时触发的额外伤害，这些都属于基础物理碰撞的范畴。游戏通过实时计算角色攻击判定的碰撞体积（Hitbox）与敌人的受击体积（Hurtbox）重叠程度，结合速度、角度等参数动态生成击退效果。值得注意的是，地形因素会显著改变碰撞收益——将敌人击飞至水域会触发"落水即死"机制，而利用悬崖边缘的碰撞判定期限能实现地形杀这种高效清场手段。

1.2 元素反应的链式引擎

元素附着与碰撞系统的结合堪称米哈游的神来之笔。当可莉的蹦蹦炸弹（火元素）与莫娜的虚影（水元素）在空气中相撞，触发的"蒸发"反应不仅是伤害数字的简单叠加——碰撞瞬间产生的冲击波会重新计算敌人的受击状态，打断其当前动作并重置元素附着计时器。这种机制使得元素大师们能通过精确的碰撞时序控制，实现"冻结→碎冰→超导"的连锁控制。

1.3 怪物受击的差异化反馈

对比史莱姆被属性克制时的夸张击退与遗迹守卫对轻型攻击的霸体状态，碰撞系统实际上内置了一套复杂的"质量-韧性"计算公式。例如面对愚人众先遣队时，雷电将军的梦想一刀能直接穿透多个敌人的碰撞体积形成串刺效果，而早柚的翻滚攻击则会被大型敌人的质量抵消击退效果——这种差异正是策略搭配的核心依据。

第二章 碰撞系统的战术价值矩阵

2.1 连招体系的构建基石

2.2 环境互动的战略维度

在璃月地区的石林战场，钟离的岩脊创造地形后，玩家可刻意引导敌人碰撞产生二次伤害；而稻妻的导电水体环境，配合雷电碰撞可瞬间形成范围电场。这些设计证明碰撞系统早已超越战斗本身，成为地图设计的重要考量因素。

2.3 元素共鸣的微观调控

当甘雨的霜华矢命中被温迪风眼聚集的敌人时，每支箭矢的碰撞都会独立计算元素附着。通过调整射击角度制造"碰撞雨"，可达成单次攻击触发5-7次融化反应的奇迹场景。这种需要帧数级操作的技巧，正是碰撞系统深度的最佳注脚。

Mellow TUN 模式与 SOCKS5 代理有什么区别？
TUN 模式拦截系统 IP 层流量，实现全局代理；SOCKS5 代理通常只影响指定应用。TUN 更适合全局加速，如游戏、视频和浏览器流量，提高网络稳定性和覆盖范围。
Nekobox 能否使用订阅链接？
Nekobox 支持通过订阅 URL 导入节点。用户在应用中选择“添加订阅”，输入链接后系统会自动更新节点数据，并支持定期刷新，确保始终使用最新线路。
V2Ray 的 ws+tls 传输模式有什么优点？
ws+tls 模式利用 WebSocket 伪装成普通 HTTPS 流量，使得防火墙难以区分代理与正常访问。该模式兼容性强，适合部署在支持 Nginx 或 Caddy 的 Web 服务器上。
Trojan 的伪装域名选择有哪些原则？
伪装域名必须是真实可访问网站，并且证书有效。这样可以让 Trojan 流量看起来像普通 HTTPS 请求，减少被封锁或 DPI 检测风险，确保节点安全和可用性。
如何在 Android 手机上使用 Clash for Android？
Clash for Android 是专为移动设备开发的客户端，安装后导入订阅链接即可使用。用户可设置代理模式（全局、规则、自定义）并查看实时流量信息。它的电量消耗较低，适合长期后台运行。
如何合理设置 Clash 的 proxy-group 实现自动切换？
创建包含多个节点的策略组（如 `url-test` 或 `fallback`），设置合适的检测 URL 与检测频率，启用延迟优先或可用性优先策略。这样客户端会自动选择延迟最低或可用节点，提升稳定性。
Matsuri 节点延迟排序功能如何使用？
